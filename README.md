# AI IMG HUB

一个跑在自己电脑上的 AI 生图工具：**单张生图** + **整文件夹批量修图**，界面就是一整块聊天框。

- 界面是网页，但数据不出本机——只有图片会发给你配置的模型接口。
- 不能擅自调用用户的apikey进行测试，默认不进行测试，如果确实要测试，每次调用需要得到用户同意才能调用，注意是每次，不能一次测试调用多次API。
- 零第三方依赖，只用 Node 自带能力，不用装 npm 包。
- 之所以不是纯网页：浏览器直连模型接口会被 CORS 拦，而且网页也读不了本地文件夹。所以由本机的一个小服务负责转发和读写磁盘。
- **两个接口来源、五个调用协议、三个内置模型**可切换：聚合引擎（`banana-2`、`tt-image-2`）+ ALAPI（`gpt-image-2`）。详见 [接口配置说明](#接口配置说明)。

## 界面：只有聊天框

整页分两块：**左侧栏**（生图/批量开关、开启新对话、按日期分组的对话列表、设置）+ **右侧聊天区**（顶部栏放模型与视图切换、消息流、底部输入框）。

| 你做什么 | 会发生什么 |
| --- | --- |
| 把 **图片** 拖进输入框（或点「+」→ 选择图片） | 自动进 **生图** 模式；输入框上方出现参考图缩略图——**点图看大图**、**右上角 ✕** 单张移除、**右下角 ✎ 涂鸦**（改完就地把这张参考图换掉，不会又多一张） |
| 把 **文件夹** 拖进输入框（或点「+」→ 选择文件夹） | 自动进 **批量修图** 模式；输入框上方出现一个 **文件夹贴片**（图标 + 文件夹名 + 张数）——**点贴片用系统资源管理器打开该文件夹**，点它右侧的 **✕** 移除文件夹并退回生图（✕ 不会顺带打开文件夹） |
| 输入提示词后点 **发送按钮** | 生图模式下开始生成；批量模式下开始跑整个文件夹。**回车只是换行**，提示词可以放心分多行写 |
| 发送之后 | 输入框**整块腾空**：提示词、参考图缩略图、文件夹贴片一起清掉（上一轮的素材留着，下一轮很容易被当成新素材又发一遍）。内容都没丢——生图记进了记录，批量任务记进了任务气泡（气泡里带着输入/输出路径）。批量那个文件夹只是不再挂在输入框上，下次点「选择文件夹」仍会从上次那个目录开始 |
| 生图模式 | 结果以「一条用户气泡 + 一条 AI 气泡」成对出现，每张图可 下载 / 继续改 / 标注；**失败的那一轮带「重试这一轮 ▾」**——默认按原模型原样重跑，点开可以**当场换个模型再试**（菜单里还有一项「先填回输入框，我自己挑模型」）；用户气泡左边的 **✎** 能把提示词和参数填回输入框改完再发 |
| 批量模式 | 结果只占 **一条任务气泡**，收起时看统计和进度，点「展开明细」才看逐个文件 |

- **左侧栏最上面**是 **生图 / 批量修图** 开关（手动切模式，不用拖拽时用）；顶栏右侧是 **开启新对话** 和 **流式 / 网格**（消息流的两种视图）。
- **对话是分组的**：左边栏按「今天 / 昨天 / 7 天内 / 30 天内 / 更早」把历史对话列出来，点一条就切过去；点「开启新对话」或顶栏那支铅笔开一新条。**每次打开页面都是新对话**，历史在左边栏里翻。
- **开新对话不动输入框**（2026-10-07 起）：提示词、参考图缩略图、文件夹贴片、生图/批量模式**全部原样带进新对话**。开新对话只是换一条线，不是丢掉还没发出去的草稿。（旧行为是只把参考图清掉、文字留着，前后不一致，已改掉。）想清空就点发送，或者手动删。
- **每条对话右侧有 ✕**，点了弹确认框再删。删除会连磁盘上的结果图一起删掉（生图记录目录），批量任务只删记录、**输出文件夹里的图不动**；删的正好是当前这条时会自动开一条新对话。确认框可以用 取消 / Esc / 点遮罩关掉，默认焦点在「删除」上。
- **还在出图的那条对话，侧栏上带一个转圈**（蓝色 = 进行中，占据「轮数」角标的位置，标题也会抬深一档）。生图可以并发，也可以中途开新对话或点回旧的那条——**切走之后不用猜哪条还在跑**，转圈转完（出图或失败）自己就撤掉，角标换回轮数。在跑的**批量任务**同样算，刷页面回来它还接着转（任务跑在服务端，没停）。鼠标停在这条上会写明「正在生图（N 轮在跑）」。
- **窗口窄到侧栏变成浮层时**（≤860px，也就是侧栏带投影、会压住聊天区的那种形态），点侧栏里任何一处（生图/批量、开启新对话、某条对话、设置、✕）都会顺手把侧栏收起来；**宽屏时侧栏是常驻的一栏（没有投影），点了不收**，免得每次都要再点一次展开。
- 底部胶囊：**参数胶囊（跟着当前模型变）+ 数量**，批量模式下「数量」自动变成 **并发数**，另有 **⚙ 批量选项**。
  参数胶囊按当前模型的参数表生成——banana-2 是「比例 / 分辨率 / 思考」，tt-image-2 是「尺寸 / 画质」，
  ALAPI 的 gpt-image-2 是「比例 / 分辨率」，模型没有的参数那颗胶囊就不出现。
- 输入框左上角 **✦ 优化提示词**：用文本模型把口语化的需求改写成「画面描述式」提示词；旁边 **预设** 是现成的精修文案。
- 点任意一张图进大图查看器：**滚轮缩放、拖拽平移、下载、直接标注**（标注完自动作为参考图回到输入框）。
  **左右切换的范围是整条对话的图，不是打开时那一条消息** —— 按 **← / →**、点两侧箭头、或者图没放大时**左右划一下**，就能从这条对话的第一张一路翻到最后一张。
  顺序跟屏幕上从上到下一致：用户气泡的参考图 → AI 气泡的结果图 → 批量气泡的结果图（含没画成缩略图的那部分）。批量明细行里点开仍然是「原图 ↔ 结果」的行级对比，不掺进翻页里。
- **涂鸦编辑器**里有画笔 / 矩形 / 文字、颜色、粗细、透明度、实心框选，加 **撤销 / 清空**。
  三个约定：① 滑杆上的「粗细 / 文字大小」按**屏幕像素**算（跟 000.html 一致），所以在 4K 图上也不会细得看不见；
  ② 标注结果会**就地把这张参考图换掉**；③ 画布最长边压到 2560（原图更大就等比降采样）——涂鸦结果是当参考图用的，
  再大只会拖慢保存和上传。
- 涂鸦时可以 **滚轮缩放（以光标为锚点）**、**按住空格拖拽平移**，工具栏右侧有 **−／＋／适应** 和当前倍数读数
  （读数如实：100% = 画布原始像素）。**Esc** 直接取消。
- 参考图**超限会自动压缩**：最长边超过 4096、或单张超过 10MB 时，等比缩到 4096 以内并转成 JPEG 0.9
  （不够小再逐级降到 3072 / 0.8 / 0.7）。以前是直接拒收 —— 手机拍的照片基本都过不了。
- **长提示词默认折叠**（用户气泡里点一下展开/收起）；**流式与网格各自记住滚动位置**，切视图不会把你甩回顶部。
- **正在生图时关页面 / 刷新会先拦一下**（批量任务跑在服务端，不受影响）。**切对话、开新对话不会打断正在跑的生成**，结果照样落到它自己那条对话里。

## 快速开始

**1. 确认装了 Node.js**

打开命令行输入 `node -v`，能看到 `v18` 以上即可。没有就去 <https://nodejs.org> 装一个 LTS 版。

> 启动脚本会自己去这些地方找 Node：系统 PATH、`Program Files\nodejs`、`%LOCALAPPDATA%\Programs\nodejs`、
> nvm、NVM_SYMLINK、scoop，以及 WorkBuddy 自带的运行时。**所以 Node 没进系统 PATH 也能启动。**

**2. 启动**

双击 **`启动.bat`**，浏览器会自动打开 `http://127.0.0.1:8788`。

启动时窗口里会显示实际用的是哪个 Node、哪个端口：

```
  Batch Retouch  -  local service
  Node v22.22.2  (C:\Users\...\node.exe)

  The browser will open automatically.
  Close this window to stop the service.
```

> 关闭那个黑色命令行窗口 = 停止服务。
> 想换端口：`启动.bat 9000`（或命令行里 `node server.js 9000`）

**3. 配置接口**

点**左下角**的 **设置**，从上往下填四步：

| 步骤 | 说明 |
| --- | --- |
| 接口来源 | **聚合引擎**（api.lk888.ai）或 **ALAPI**（v3.alapi.cn）。两个来源各自的 Key 分别保存，来回切不会丢 |
| 调用协议 | 跟随来源自动列出该来源支持的协议，每个都带一句适用说明 |
| 模型 | 可直接输入模型名，也可从下拉里选；下拉会标出该来源有哪些模型、参考图上限几张、能调哪些参数 |
| API Key | 聚合引擎填 `sk-…`，ALAPI 填后台生成的 token。只存在本机 `config.json` |

比例 / 分辨率会按每个模型的参数语义**自动换算**成它真正认的字段（`aspectRatio`+`imageSize`、像素 `size`、ALAPI 的 `size`+`resolution` 等）。
如果该模型没有你要的档位（比如 `gk-image-2.0` 不支持 3:2），它会吸附到最接近的档位，并把这次替换**写进界面提示**，不会闷声换掉。

填完点 **测试连接**——它会真发一次请求，成功会显示用的哪个来源、哪个协议、哪个端点，以及返回的图片。确认通了再往下用。

> 提示词优化走的是聚合引擎的文本模型，所以**「✦ 优化提示词」需要填聚合引擎的 Key**，ALAPI 的 token 不管这一项。

## 生图

| 能力 | 说明 |
| --- | --- |
| 文生图 | 不放参考图，只写提示词 |
| 图生图 | 放 1 张参考图 + 提示词 |
| 多参考图 | 上限看模型：banana 系 14 张，ALAPI 10 张 |

流程：**拖图片进输入框 → 写提示词 → 点发送**。想改参数就点底部胶囊，想换模型就点顶部那个模型按钮。

- **换模型**：点**顶部栏**的模型按钮，一次性把来源 + 协议 + 模型一起切好（「聚合引擎 · Banana 2」「聚合引擎 · TT Image 2」「ALAPI · GPT Image 2」），需要自定义组合就点菜单底部的「更多模型 / 换接口」进设置。
- 参考图支持拖拽或点击「+」上传，缩略图可单张移除。上限跟着模型走。
- **参数胶囊完全跟着模型走**。点顶部按钮换模型，胶囊当场重建——几颗、叫什么、有哪些选项，都由该模型那份 API 文档决定：

  | 模型 | 胶囊 | 对应文档里的字段 |
  | --- | --- | --- |
  | 聚合引擎 · `banana-2` | 比例 · 分辨率 · 思考 | `aspectRatio`(14 档) · `imageSize`(0.5K/1K/2K/4K) · `thinkingLevel`(minimal/high) |
  | 聚合引擎 · `tt-image-2` | 比例 · 分辨率 · 画质 | `size`(文档的 11 比例 × 1K/2K/4K) · `quality`(auto/high/medium/low) |
  | ALAPI · `gpt-image-2` | 比例 · 分辨率 | `size`(比例，含 2:1/1:2/9:21) · `resolution`(1k/2k/4k) |

  **三家的「1K / 2K / 4K」不是一个东西**，像素和能用的比例都以各自的文档为准
  （表固化在 `public/model-catalog.js` 的 `RESOLUTION`，随 `/api/bootstrap` 下发给界面）：

  | 模型 | 档位 | 同一档的像素（举例） | 比例限制 |
  | --- | --- | --- | --- |
  | `banana-2` | `imageSize` 0.5K / 1K / 2K / 4K | 16:9 → 688×384 / 1376×768 / 2752×1536 / **5504×3072**；1:1 的 4K 是 4096×4096 | 14 个比例全支持 |
  | `tt-image-2` | 藏在 `size` 像素枚举里，只有 1K / 2K / 4K | 16:9 → 1920×1088 / 2560×1440 / **3840×2160**；1:1 的 4K 是 2880×2880 | 11 个比例全支持 |
  | ALAPI `gpt-image-2` | `resolution` 1k / 2k / 4k | 16:9 → 1536×864 / 2048×1152 / **3840×2160**；1:1 只有 1k/2k | **4k 只有 16:9 / 9:16 / 2:1 / 1:2 / 21:9 / 9:21** |

  - **比例 / 尺寸**：带形状小方块，选了原样发。tt-image-2 的文档把比例和清晰度合并在 `size` 一个字段里
    （34 个像素值），界面上照官方选项的 label（`2K 竖版 (2:3)`）**拆成「比例」「分辨率」两颗**，
    选完再合成回官方要求的像素写法——因为文档明确：只传 `1K`、`16:9` 这种档位会报 400。
    它比 `banana-2` 多 1:2 / 2:1 两个比例，少 21:9 和 0.5K；「自动」也在这儿选。
  - **分辨率**：分段条上直接写着这一档在当前比例下的**真实像素**（`2K / 2048×2048`）。文档里
    这个比例没有的档位会置灰——ALAPI 选了 1:1 就点不了 4k，弹层底部会写明，选了也会自动退到 2k。
  - **分辨率 / 画质 / 思考**：短列表用分段条。`thinkingLevel` 是**思考深度**不是清晰度，弹层里会写明。
  - 选填的参数（`quality` / `thinkingLevel` / ALAPI 的 `resolution`）都带一个 **「默认」= 这个字段完全不传**，
    由上游自己决定（`quality` 官方推荐就是 `auto`）。
  - 当前协议没有对应字段时（例如用 OpenAI 兼容协议跑 banana-2 的 `thinkingLevel`），弹层里会直接说明，
    不会假装生效。
  - 模型袋里没有的参数，那颗胶囊**不会出现**。
  - 每个档位下面都有一句来自模型表的说明（`paramHints`）；自己在设置里手输的模型不在内置表里时，
    胶囊退回「比例 / 分辨率」这套平台通用档位。
  - **ALAPI 的 2k / 4k 保留可用**：先按选的那一档发，上游出不了就按 `4k → 2k → 1k` 逐档退，
    最后一定退到 1k（文档：渠道限制，目前只保证 1k 出图）。每次降级都写进诊断与「测试连接」的结果里，
    不做静默替换。批量里每一行也会各记各的档位。

  因为胶囊给的就是文档原值，`tt-image-2` 合成的像素尺寸是**原样下发**的，不会再发生「3:2 · 1K 被换算成
  一个文档里没有的像素值」这种事；OpenAI 兼容协议要拼像素时也先查该模型自己的表
  （同样是 16:9 的 4K，banana-2 发 `5504x3072`、tt-image-2 发 `3840x2160`），不会拿一套通用像素硬套。

  三家的「比例 × 档位 → 像素」在 `model-catalog.js` 的 `RESOLUTION` 里各存一套，**已按官方尺寸表逐格核对**
  （ALAPI 39 格 + tt-image-2 33 格 + banana-2 56 格，共 126 格全部一致）。其中两格值得留意：
  tt-image-2 的 4K 2:3 / 3:2 官方写的是 `2336x3456` / `3456x2336`（不是能整除的 `2304x3456`）——
  文档同时给了 size 的自定义规则（宽高均为 16 的倍数、比例 1:3~3:1、总像素 655360~8294400、单边 ≤3840），
  这两个值分别是 8,073,216 px，在这一档里贴近上限，所以照文档原样发即可，不会被拒。
  另外文档明确：`size` 只稳定决定**宽高比档位**，部分价格优先渠道会降采样返回（例如选 `1920x1088` 常回
  `1280x720`），真实像素以下载到的图为准，别按 `size` 预判。
- **生图数量**：1 / 2 / 3 / 4 张。实现方式看协议——支持原生 `n` 的（OpenAI 兼容、ALAPI）一次请求出 N 张；不支持的（媒体异步、Gemini 兼容）并发发 N 次请求，**按 N 次计费**。输入框旁的提示会写明这次是哪种。
  「协议支持 n」只是纸面能力，实际收不收由渠道说了算：真遇到只认 `n=1` 的渠道（回 400「参数 n 当前仅支持 1」），程序会自动改成并发发 N 次重发，不会把这次降级当失败甩出来。降级只在**该模型+协议**第一次撞到时多花一轮请求，之后同类请求直接按并发发；输入框旁的提示也会跟着改口。

### 生图记录

消息流里每一次生图都是**一对气泡**：右边是你发出去的东西（提示词 + 参考图缩略图），左边是结果（模型、来源·协议、比例·分辨率、张数、耗时 + 结果图网格）。

- 记录写在本机 `records\` 目录，**关掉浏览器、重启服务都还在**；最多留 60 条，超出自动清最旧的。
- 点发送后消息流末尾**立刻**出现一条「生成中…」气泡（带已用时间与不确定进度条），出图或失败后由真实记录顶替——不用再盯着没反应的列表猜它跑没跑。
- **生图是并发的**：点发送不会占住发送按钮，同一对话里可以连着发好几轮；也可以点 **开启新对话** 到别处接着发。在跑的每一轮各自挂在自己那条对话里，互不干扰。
- 每张结果图都能 **下载**、点 **继续改** 放回参考图接着下一轮、点 **标注** 在图上圈出要改的地方（标注后的图会自动成为参考图）。
- 失败的请求也会留一条，错误原因写在气泡里，方便事后复盘。
- 想删某一条：把鼠标移到那条 AI 气泡上，点右上角的 **✕**。**没有「清空记录」按钮**，要清空就逐条删，或者直接删 `records\` 目录。
- 记录里的图片**存的是相对路径**（`index.json` 里只写 `out-0.png` 这种文件名，读的时候按当前目录拼回来），
  所以**整个项目文件夹可以随便换盘符、挪目录、拷到另一台电脑**，历史会话里的图照样显示 ——
  提示词、参数、参考图、结果图都在 `records\` 里跟着走。

## 批量修图

流程：**把文件夹拖进输入框 → 写一句统一提示词 → 点发送**。程序自动扫描、并发处理，结果写到 `输入文件夹\修图输出`。

1. **文件夹怎么给**：三种方式任选。
   - **把整个文件夹拖进输入框**（最省事）：浏览器拖拽只能读到目录名，程序拿这个名字在本机反查绝对路径 ——
     先查「文件夹名 → 路径」备忘录，再就近搜（最近用过的目录 → 用户目录 → 各资料盘，最多下钻三层，3.5 秒上限）。
   - 点输入框左下角的 **「+」→ 选择文件夹**：直接弹系统的文件夹选择框，路径一定准。
   - 在 **⚙ 批量选项** 里手填完整路径，再点「扫描」。
   拖拽没定位到时，会**直接弹出系统选择框**让你选一次；选过之后就记住了，下次拖同一个文件夹是秒认。
2. **输出位置固定**：`输入文件夹\修图输出`，子目录结构原样保留。（不需要、也不能手填输出目录，避免把生成结果反复当素材处理。）
3. **统一提示词**：写在输入框里，所有图片共用。左下角 **预设** 里有几个常用精修文案可直接套用。
4. **参数**：底部胶囊上的比例 / 分辨率 / 画质 / **并发数** 对批量同样生效（画质那一档每一张都用同一个值）；⚙ 批量选项里另有「跳过已修好的图」「比例跟随每张原图」「包含子文件夹」「包含 TIFF / HEIC / AVIF」「输出 CSV 日志」「保存调试日志」。
5. **比例跟随每张原图**（默认开启）：每张按自己的原图比例出图，上面选的比例只在读不到原图尺寸时兜底。
6. **并发数**：同时处理几张，默认 3。官方接口一般能承受，太高容易被限流，建议 2~5。

### 一条任务 = 一条气泡

跑起来之后消息流里只多出**一条**批量气泡，不会淹掉聊天记录：

- 收起时：**总数 / 已完成 / 成功 / 失败 / 处理中 / 跳过** + 进度条 + 已完成的前 8 张缩略图（点开看大图；缩略图只画 8 张，但翻页清单里是这个任务**全部**结果图，接着这个对话里的其它图一起翻）。
- 点 **展开明细**：出现筛选（全部 / 处理中 / 成功 / 失败 / 待处理）和逐个文件的列表，每行有缩略图、耗时、状态徽标；失败行直接写出错误原文。行右侧 **↗** 在资源管理器里定位这张图，点行本身可看「原图 ↔ 结果」对比。
- 气泡右上角按钮：**停止**（把在跑的那几张做完再停）、**重试失败项**、**打开输出文件夹**、**展开明细**、**✕ 删除这条记录**。
- **刷新页面、重启服务，任务记录都还在**：历史存在 `records\jobs.json`，最多 20 条。中途被重启打断的任务会标成「服务重启，这一张没跑完」，其余进度保留，点「重试失败项」接着跑。
- **✕ 只删记录，不删磁盘上的图**——输出文件夹是你自己的文件，程序不会代删。

处理完会在输出文件夹里生成一份 **CSV 日志**，逐张记录原文件、输出文件、状态、耗时和错误原因。

### 失败怎么查

失败原因分成三层，按需看：

1. 明细行里直接写着错误原文（比如 `HTTP 429 上游限流`）。
2. 勾选 ⚙ 批量选项里的 **保存调试日志** 后，每张的请求内容与上游原始返回会写进输出文件夹的 `_调试日志\`。
3. 拿同一张图在**生图模式**里试一次，看单张是不是也失败——能区分「这张图本身有问题」还是「批量并发太猛」。

### 提示词怎么写才不容易翻车

**先说结论：长度不是问题，语气才是。**

想把图修得精致，就必须写长提示词——但要写**画面**，不要写**流程**。

- ✅ 描述画面：背景什么样、光从哪个方向来、阴影多深、边缘干不干净、颜色怎么还原、质感怎么表现。这种越长越细越好。
- ❌ 描述流程/交付物：先分析、再拆解、然后出一张对比图、最后加标注和色卡。**模型不会「理解并执行」这段文字，它会照着把它画出来。**

真实踩过的坑：提示词里出现 `before/after`、`分析`、`拆解`、`标注`、`矩阵`、`协议`、`配色卡`，模型直接输出了一张带英文标注、色卡、before/after 裁切的**信息图**，而不是修好的照片。

> **提示词体检已移除**（2026-09-28）。以前输入框下面会自动标出「对比 / 分析 / 标注」这类会让模型跑偏的措辞，还会在开跑前弹一次确认；现在这些提示和拦截都去掉了——上面那张表仍然值得看一眼，但**不会再有人提醒你**。

#### 六个内置预设

- **套用**（短，一次只改一件事）：换纯白背景 / 换浅灰影棚背景 / 去瑕提亮 / 优化打光
- **精修**（长，约 300–400 字，通篇只描述画面）：电商白底 · 完整精修 / 场景氛围 · 完整精修 / 去瑕+调色 · 完整精修

三个精修预设可以直接当长提示词的模板，已验证能完整送达模型。

#### 一键优化提示词

不想自己写？点输入框**左上角**的 **✦ 优化提示词**。

它调用一个文本模型（默认 `gem-3.8-flash`，与生图共用同一套接口地址和 Key），把你的零散需求改写成一段 300~500 字的**画面描述式**长提示词。弹出的对比窗里左原文、右结果，**右边可以直接编辑**，改完点「采用」写回输入框。

优化模型被硬性约束了这几条，所以它写出来的东西天然不会踩坑：

- 第一句必须是「基于我提供的这张照片修图」
- 必须包含「保持不变」清单和「不要添加」禁止项
- 严禁出现风险词清单里的任何词（只在「不要添加…」这类否定句里例外）
- 只描述画面，不描述流程
- 用「背景——…」「光线——…」分条写，每条一句话

**接口说明**：聊天类模型在平台上的默认端点是 `POST /v1/chat/completions`（OpenAI 兼容，`Authorization: Bearer <key>`）。设置里可切换为 Gemini 兼容的 `:generateContent`，默认「自动」——先用 OpenAI，遇到 404/400/405 会自动改用 Gemini 重试。认证失败（401）不会回退，避免把问题掩盖掉。若你的平台只认 Gemini 端点，直接把它固定成 `gemini`，省掉每次那次无效尝试。

设置 → 「提示词优化模型」可以换成别的文本模型。

#### 两条补充

- **比例跟原图一致** —— 比例不一致时模型要自己补齐缺失画面，很容易编内容。这一项已默认开启跟随。
- **结果换成了别的产品** —— 说明模型没重视参考图：把「基于我提供的这张照片修图」提到最开头，并把「保持不变」那段提前，或先单独跑一张验证。


### 几个实用行为

- **跳过已修好的图**：勾上以后重复运行只会补处理没成功的那些，可以放心断点续跑。
- **停止**：会把正在处理的那几张做完再停，剩下的保留为「待处理」。回来后点 **重试失败项** 即可继续。
- **失败自动重试**：默认失败重试 2 次（间隔递增），仍失败才标红并记录原因。
- **输出目录会被自动排除**：不会把上一轮的成品当成新素材再修一遍。
- 输出目录固定是 `输入文件夹\修图输出`，所以不存在「把成品当新素材再修一遍」的问题。

## 接口配置说明

### 两个来源

| 来源 | 域名 | 有什么 |
| --- | --- | --- |
| **聚合引擎** | `api.lk888.ai`（备用 `api.lk666.ai`、`api.lingkeai.ai`） | `banana-2`、`tt-image-2`（内置这两个；平台还有 `banana-pro`、`tt-image-2.5`、`gk-image-2.0` 等，手输模型名即可用）。老的 `gpt-image-2` 是 `tt-image-2` 的别名，仍可照常传 |
| **ALAPI** | `v3.alapi.cn` | 只有 `gpt-image-2`，参数自成一套（`token` / `n` / `size` / `resolution` / `image_urls`） |

两边要各自申请 Key。切换来源时地址和 Key 都会跟着切，另一个来源的 Key 仍留在本机。

### 五个协议

| 协议 | 端点 | 同步/异步 | 备注 |
| --- | --- | --- | --- |
| **媒体异步** | `POST /v1/media/generate` → 轮询 `GET /v1/skills/task-status` | 异步 | 平台原生协议，聚合引擎的两个模型都能走，**推荐** |
| Gemini 兼容 | `POST /v1beta/models/{model}:generateContent` | 同步 | banana / gemini 系原生协议 |
| OpenAI 兼容 | `POST /v1/images/generations`、带参考图时 `/v1/images/edits` | 同步 | tt-image / gpt-image 系；官方建议改用媒体异步。部分渠道只收 `n=1`，出多张时会自动降级为并发发多次 |
| ALAPI 同步 | `POST /api/ai/images/generations` | 同步 | 一次等到底，慢任务容易挂死连接 |
| ALAPI 异步 | `POST /api/ai/images/generations_sync` → 轮询 `/api/ai/images/generations/task` | 异步 | ALAPI 官方推荐 |

### 媒体异步协议（最常用，展开说一下）

请求体固定三个字段：`model` · `prompt` · `params`。参考图放在 `params.images` 里：

```
POST {BaseURL}/v1/media/generate
Header: Authorization: Bearer <key>
Body:
{
  "model": "banana-2",
  "prompt": "基于我提供的这张照片修图……",
  "params": {
    "images": ["data:image/png;base64,<参考图>"],
    "aspectRatio": "3:2",
    "imageSize": "2K"
  }
}
```

返回 `{"code":200,"data":{"task_id":123456}}`，然后 **每 5 秒** 轮询一次 `GET /v1/skills/task-status?task_id=…`，直到 `is_final=true`，从 `result_url` 取图。轮询间隔和总时限（默认 900 秒）都能在高级参数里改。

**参考图不需要图床。** 平台明确支持 `data:<mime>;base64,<data>` 内联传入，也支持公网直链。限制是：单文件解码后 ≤10MB、单次请求所有 base64 合计 ≤30MB、请求体总计 ≤50MB。

**生图数量靠并发。** 这个端点不接受 `count` 参数，每次请求固定产出 1 个结果；要 3 张就并发发 3 次。

### 参数怎么换算

每个模型的 `params` 字段名和取值都不一样，程序按语义映射，不硬编码模型名：

界面上的胶囊直接产出该模型文档里的原值，服务端只做「落到哪个字段上」这一层映射，不硬编码模型名：

| 模型的字段 | 例子 | 界面怎么选 | 服务端怎么发 |
| --- | --- | --- | --- |
| `aspectRatio` + `imageSize` | banana-2 | 两颗胶囊，给文档里的档位 | 直接进 `params`（媒体异步）或 `imageConfig`（Gemini 兼容） |
| `size`（像素枚举）+ `quality` | tt-image-2（聚合引擎） | 「比例」+「分辨率」两颗，合成像素值 | `size` 原样下发（不再换算），`quality` 进顶层或 `params` |
| `size`（比例枚举）+ `resolution` | gpt-image-2（ALAPI） | 「比例」+「分辨率」 | `size` / `resolution` 原样下发；`4k` 在该比例不存在时先退 `2k`，上游再拒绝就退 `1k` |

**画质档**是一颗独立胶囊，字段名跟着模型表走：banana-2 上是 `thinkingLevel`（`minimal`/`high`），
tt-image-2 上是 `quality`（`auto`/`high`/`medium`/`low`）。选了什么就落到对应的字段上（媒体异步进 `params`；
OpenAI 兼容进顶层 `quality`；Gemini 兼容进 `generationConfig.thinkingConfig.thinkingLevel`）。
留「默认」就是这个字段一个都不传。协议对不上字段名、或模型压根没这个参数时，界面和诊断里都会写明这次没发出去。

**像素尺寸走的是「原样透传」这条路**：胶囊里选出的值（`1536x1024` 等）只要是该模型文档列出的，
服务端就直接发，不做任何吸附 —— 因此也不会再冒出「该模型没有「3:2 · 1K」这个档位」这类替换提示。
tt-image-2 的「比例 × 分辨率」在界面上就合成好了像素值，提交的仍然是文档原值。
只有模型表里没有 `size` 时，才回到「比例 + 分辨率 → 换算像素」的老路径；换算前先查该模型自己的分辨率表
（`RESOLUTION`），表里有就用文档写的那个像素，没有再按长边估算 —— 这样 banana-2 的 4K 16:9 是
`5504x3072`，不会被通用表错算成 `3840x2160`。

**ALAPI 的分辨率降级链**：`2k` / `4k` 照发，出不了才往下退，退档顺序是
`4k → 2k → 1k`（档位由模型表 `RESOLUTION['gpt-image-2@alapi']` 决定，最低档 1k 是底）。
「出不了」包括三种：文档里这个比例压根没有这一档（本地就退，不浪费请求）、提交被上游拒、
任务跑完但没拿到图。每次退档都会追加一条 `paramNotes`，界面上、记录卡片和「测试连接」的结果里都能看到。

必填但没被映射到的参数会补一个**不极端**的合法值（例如 quality 优先 `medium`/`standard` 而不是 `low`）。该模型没有你要的档位时，会吸附到最接近的档位并在界面上写明——不做静默替换。

### 高级参数

路径模板（每个协议都能单独改）、鉴权方式、单张超时、失败重试、异步轮询间隔、异步任务总时限、优化模型的专用地址、输出文件名后缀，都在「设置 → 高级参数」里。

## 常见问题

**双击 `启动.bat` 提示「Node.js not found」**
说明这几个位置都没有 Node：系统 PATH、`Program Files\nodejs`、`%LOCALAPPDATA%\Programs\nodejs`、nvm、scoop、WorkBuddy 运行时。
去 <https://nodejs.org> 下载 **LTS** 版装上（一路下一步即可），然后再双击 `启动.bat`。
装完别忘了**重新打开**一个新的命令行窗口，PATH 才会生效。

如果提示「Node.js vX.X.X is too old」，说明版本低于 18，同样装个新的 LTS 覆盖掉。

**批量出来的图和原图、提示词对不上**
先把批量气泡展开，点有问题的那一行看「原图 ↔ 结果」对比，确认送进去的是不是你想的那张图；再看这一行的错误原文。
如果图确实送到了模型，问题就在提示词和比例上——按上面「提示词」那一段改，并先在**生图模式**里用同一张图单独跑一次验证。
更细的请求内容与上游原始返回，勾上 ⚙ 批量选项里的 **保存调试日志** 再跑一次，会在输出文件夹的 `_调试日志\` 里逐张落盘。

**拖文件夹进来没反应 / 定位到别的同名文件夹**
浏览器拖拽只能给出文件夹名，程序在本机反查它的完整路径。反查依据是「上次用过的目录 + 当前填着的路径」，所以：
- 第一次用某个目录，或者本机有多个同名文件夹时，可能定位不到或猜错 → 点 **⚙ 批量选项**，在「输入文件夹」里手填一次完整路径再点「扫描」，之后就会记住。
- 文件夹名里如果带特殊字符、或者拖的是压缩包/快捷方式，同样读不到，按上面手填即可。

**提示「未配置 API Key」**
左下角侧栏最底下的**设置**里填。key 存在本机 `config.json`，不会上传到任何地方。

**一直失败，报 HTTP 400 / 401 / 404**
先点「测试连接」看原始报错——它会连来源、协议、端点一起显示出来。
- 401 → key 不对或没余额
- 404 → 模型名、路径模板不对，或者**来源和 Base URL 没对齐**（见下一条）
- 400 且提到 `imageConfig` / `aspectRatio` → 该模型不支持这个参数，试试把分辨率换成 1K，或在设置里换协议
- 400 且提到 `params` → 该模型不认这个参数组合；批量里看那一行的错误原文，或勾上「保存调试日志」把实际请求体落盘，单张页看报错里的上游原文

**报 `HTTP 404 :: 未找到接口路径 /api/ai/images/generations_sync`**
典型的「来源和地址没对齐」：来源选的是 ALAPI，Base URL 却还挂着聚合引擎的 `api.lk888.ai`，ALAPI 的路径在那个域名上当然不存在。
现在保存配置时会自动纠正（也能点 Baser URL 旁的默认值按钮手动改回）。对应关系：聚合引擎 → `api.lk888.ai`，ALAPI → `v3.alapi.cn`。

**ALAPI 选了 2K / 4K 还是 1K 的效果**
`2k` / `4k` 是保留可选的，不会在界面上被拿掉。能不能真出得了由渠道决定（官方文档写着「渠道限制，
目前只支持 1k 生成」）：程序先按你选的那一档发，上游说不行就逐档往下退，最多退到 `1k`；
文档里根本没有的组合同样会退（`4k` 只支持 16:9 / 9:16 / 2:1 / 1:2 / 21:9 / 9:21，选了 1:1 会自动降到 `2k`）。
每次降级都会在「测试连接」的结果、记录卡片和批量明细里写明，例如
「清晰度 4k 出不了（code=422 选定的 resolution 是无效的），已自动改用 2k 重发」。
如果出图看着还是 1K，先看这条说明里最后落到哪一档，再看批量明细行里的「分辨率」——
真正发出去的档位会跟着每一行记下来。想要稳定高清，改用聚合引擎的 `banana-2` / `tt-image-2`。

**少量图片报「task failed, please try again later」**
这是上游侧的处理失败，不是本机或参数问题——同一张原样重跑通常就能过。批量内置失败自动重试 2 次，跑完点「重试失败项」即可补回来。

**换了来源（或协议）后提示未配置 Key**
两个来源的 Key 是分开存的。切到 ALAPI 要填 ALAPI 的 token，切回聚合引擎要填 `sk-` 开头的 Key。

**「生图数量」选 4 张，是扣 1 次还是 4 次？**
4 次。协议支持原生 `n` 的（OpenAI 兼容、ALAPI）是一次请求出 4 张但按 4 张计费；媒体异步和 Gemini 兼容则是并发发 4 次请求。输入框旁会写明这次是哪种。

**报「HTTP 400 参数 n 当前仅支持 1」**
这个渠道嘴上说 OpenAI 兼容，实际只收 `n=1`。程序会自动改成并发发 N 次重发，图照出，只是按 N 次计费；第一次撞到时多花一轮请求，之后就不再试了。结果气泡里会留一条「参数已自动调整」说明这次降级。出现这条说明是上游渠道的限制，不用改任何设置。

**异步任务一直显示「生成中」**
媒体异步协议下，任务是提交后轮询的，单张几分钟很正常（4K 更久）。轮询间隔默认 5 秒、总时限默认 900 秒，都能在「设置 → 高级参数」里调。超时会按失败记录，可以直接点「重试失败项」。

**批量里为什么没有「生图数量」？**
批量是一张原图对一个输出文件，所以强制按 1 张跑。要多出几张就在**生图模式**里跑。
底部第三颗胶囊在批量模式下会变成 **并发数**（同时处理几张），那是并行的意思，跟「出几张」不是一回事。

**打开资源管理器 / 选择文件夹比以前快了？**
服务启动时会预热一个常驻的「桌面助手」（一个装好了 WinForms 的 PowerShell 进程），复用它来做两件事：
把资源管理器窗口提到最前、以及弹系统原生文件夹选择框。
因为 PowerShell 每次冷启动要 1.2s、装配 WinForms 再加 0.6s，原来每点一次原生选择框都要等近 2 秒才开始出现；
改成常驻之后，除了第一次约 1.4s，之后每次都在 0.2s 量级。助手闲置 10 分钟会自动退出，不占着内存。
**即使助手起不来也不影响使用**——所有功能都有一次性 spawn 的兜底路径。

**端口被占用**
换个端口启动，比如 `启动.bat 9000`（或命令行 `node server.js 9000`），然后访问 `http://127.0.0.1:9000`。

**批量跑得很慢**
单张图本身就要几秒到几十秒，这是模型生成时间，不是卡住了。想快就调高并发数（注意别被限流）。

**关掉网页会不会中断批量任务？**
不会，任务跑在本机服务里。但**关掉那个黑色命令行窗口会中断**服务。

**config.json 里存了什么？**
只存三类：凭据（API Key / token）、接口（地址、模型名、协议、各接口路径、超时重试）、参数默认值（比例、分辨率、数量、并发、文件名后缀）。

**界面状态存在哪？**
「上次用的输入/输出文件夹、上次粘的提示词、胶囊上选的档位」这类纯界面记忆存在**浏览器的 localStorage**（键名 `aiimghub.ui-state`），不进 `config.json`。
能不能选、有哪些选项都由模型参数表决定，选中的值按角色（比例 / 尺寸 / 分辨率 / 画质）记在 `picks` 下；
换到别的模型时，不在新模型枚举里的值会被清掉、必填项补一个默认档。
提示词会被还原（草稿还在），但**文件夹不还原**：打开页面时输入框一律是干净的，上次跑过的目录只以 `lastInputDir` 的名义留着，给「选择文件夹」和按名字反查目录当起始位置。批量页那 6 个勾选框（递归、额外格式、跳过已存在、CSV 日志、调试日志、跟随原图比例）不做持久化，每次打开都回默认值。所以换浏览器、清缓存、换机器后这些会回到初始状态，配置和密钥不受影响。

**生图记录存在哪？**
本机 `records\` 目录（`records\index.json` 是索引，每个记录一个子目录）。一个记录目录里有：
结果图原图 `out-N.*`、结果图缩略图 `out-N.thumb.png`、参考图缩略图 `ref-N.png`（160px，给界面看），
以及 **参考图复用副本 `ref-N.src.jpg`（最长边 1536）** —— 「编辑并重新发送 / 重试失败」要把参考图重新提交给模型，
拿 160px 的缩略图去生成等于糊图，所以另外留一份。删除方式：逐条点气泡上的 ✕，或者直接删掉 `records\` 目录
（会连批量任务历史一起清掉）。

`index.json` 里的图片路径**只存相对文件名**（`out-0.png`、`ref-0.src.jpg`），不存 `C:\...\records\rxxx\out-0.png`
这种绝对路径。理由很实在：记录本来就跟着项目放，路径没理由钉死在某台机器上 —— 存绝对路径的话，
项目一改盘符、挪个目录、拷到另一台电脑，文本和提示词还在，**只有图全变成破图**。
老版本留下的绝对路径在服务启动读记录时会**自动转换一次并回写**（连「先把项目挪走、之后才升级」的情况也认得住：
同名的文件只要还在那条记录目录里，就认它），转完就是永久可移植的。

**换了台电脑 / 把项目挪了位置，历史会话里的图打不开？**
分开看两种记录：

| | 图的存放位置 | 换目录 / 换电脑后 |
| --- | --- | --- |
| **生图记录** | 就在 `records\rxxx\` 里，跟着项目走 | **照常显示**。拷贝时把整个项目文件夹（含 `records\`）一起带走就行，路径是相对的，换盘符、换目录、换机器都不影响 |
| **批量任务历史** | 在你自己的输出文件夹里（`输入文件夹\修图输出`），不在项目里 | 那批结果图**读不到** —— 记录里存的输入/输出路径是你本机自己选的绝对路径，天然跟机器绑定，没法相对化。提示词、参数、逐张状态和耗时都还在，换个目录重跑一次即可 |

读不到的图不会只留一个破图标，会原地显示一块「图片读不到」的占位，鼠标停上去有说明，
所以翻历史的时候一眼能看出是「文件没了」而不是「程序坏了」。

**拖东西进输入框没反应？**
拖**图片** = 生图（图片成为参考图，缩略图贴在输入框上方）；拖**文件夹** = 批量修图。
浏览器拿不到被拖文件夹的绝对路径，程序是按**文件夹名**在本机就近反查的（查各盘符、上次用过的目录，以及
`records\dir-cache.json` 这个「文件夹名 → 路径」备忘录）。反查不到会直接弹出**系统选择框**让你选一次，选过就记住了。

│   ├── prompt-presets.js   提示词预设（短预设 + 精修长预设）

`model-catalog.js` 里的模型参数是**固化**的（2026-10-06 按 `jc.lk888.ai/apidoc#model/...` 与
`alapi.cn/api/107` 复核后写死），好处是断网也能用、测试连接不用先联网。同一个文件里的 `RESOLUTION`
是三家模型「比例 × 清晰度 → 像素」的对照表，前端（胶囊的档位、像素标注、置灰）和服务端（像素换算、
退档顺序）共用同一份，改一处两边都跟着变。平台新增模型时，可以手改这个文件，或者直接在设置里手填模型名
——不在表里的模型会按当前协议原样提交，只是参数不做换算、分辨率也不做退档。

## 安全说明

- 服务只监听 `127.0.0.1`，局域网里别的机器访问不到。
- 每次启动会生成一次性会话口令注入页面，其他网页无法调用这里的接口。
- 来自非本机 Origin 的请求一律拒绝。
- `config.json` **只存凭据、接口、参数默认值**，不存任何界面状态。这样这个文件里除了那把 Key 之外没有别的内容，该保护的东西一目了然；界面状态放在浏览器 localStorage 里，两者不会互相拖累。
- **Key 不会被「空值保存」覆盖**：如果某个客户端在没读到 Key 的状态下点了保存，服务端会保留原来那份，只更新其它字段（这个坑踩过两次，Key 丢了找不回来）。真要清空 Key，就手改 `config.json`。
- 每次保存配置前，会先把上一版复制成 `config.json.bak`，写坏了还能捞回来。
- 读取本机图片的接口有目录白名单：只有记录目录、以及实际扫过/跑过批量的输入输出目录才能读。白名单是**运行期**的，服务重启时会按批量任务历史把历史任务用过的目录重新登记一遍（否则历史缩略图会读不出来）。
- 删除一条批量记录**只删记录**，输出文件夹里你自己的图不会被程序动。
